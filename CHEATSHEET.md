# 📚 Справка Neovim (Leader = Space)

Открыть в редакторе: **F1** · **Space K** · **Space hk**  
Закрыть справку: **q** · **Esc** · **F1**

В статусбаре слово `python` — это **тип файла**, а не виртуальное окружение.

## 🐍 Python

### Виртуальное окружение (как Interpreter в PyCharm)

| Клавиши / команда | Действие |
|-------------------|----------|
| `Space cv` | **выбрать venv** (список окружений) — работает в любом файле, не только `.py` |
| `:VenvSelect` | то же самое |
| `:!python3 -c "import sys; print(sys.executable)"` | какой Python сейчас используется |
| `:lua =vim.fn.exepath("python3")` | путь к python из Neovim |

Отладка, тесты и REPL берут интерпретатор в таком порядке:
`$VIRTUAL_ENV` → `.venv` / `venv` / `env` в корне проекта → то же в текущей директории
→ conda → системный `python3`. Поэтому проекты с папкой `venv/` (а не `.venv/`)
тоже работают. Смотрится от корня проекта, а не от `cwd`.

**Про uv:** `uv` установлен (`/opt/homebrew/bin/uv`). venv-selector умеет PEP-723
скрипты — если в начале `.py` файла есть блок
```python
# /// script
# dependencies = ["requests"]
# ///
```
то окружение создаётся и синхронизируется сам через `uv sync --script`.
Для обычного uv-проекта (`uv.lock` + `pyproject.toml`) venv создаётся командой
`uv sync`, а плагин подхватывает его как `.venv/bin/python`.

**Как подключить своё окружение:**

1. Создай venv в корне проекта (если ещё нет):
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   # полезно для Neovim:
   pip install ipython debugpy pytest
   ```
2. В Neovim открой `.py` файл → нажми `Space cv`
3. Выбери `.venv` (или conda / другое)
4. Если автодополнение «старое»: `:LspRestart`

По умолчанию ищется `./.venv/bin/python`, иначе системный `python3`.  
Выбор через `Space cv` запоминается для проекта и подключает LSP (pyright/ruff) + отладку.

## 📂 Explorer (Snacks)

Проводник neo-tree удалён — остался один Explorer. Вкладок «Файлы / Буферы / Git» больше нет.

| Клавиши | Действие |
|---------|----------|
| `Space E` | **Explorer** (плавающее дерево файлов), корень проекта |
| `Space e` | то же самое (алиас LazyVim) |
| `Space ff` | поиск файлов по всему проекту |
| `Space eb` | буферы (Snacks) |
| `Space eg` | панель коммита: файлы + Commit / Push |
| `l` / `Enter` | открыть файл или войти в папку |
| `h` | выйти из папки / закрыть |
| `a` | создать файл / папку |
| `d` | удалить |
| `r` | **переименовать файл/папку** |
| `m` | переместить (move) |
| `q` / `Esc` | закрыть Explorer |

Explorer показывает **все** файлы, включая `.env`, `.gitignore`, `.venv`, `.config`
и всё, что лежит в `.gitignore`. В дефолтах snacks для этого выключены
`--hidden` и `--no-ignore`, поэтому такие файлы не находились вообще; в
`lua/plugins/ui.lua` для `explorer` и `files` включены `hidden = true` и
`ignored = true` (служебное содержимое `.git` исключено).

Корень проекта ищется вверх от текущего файла: LSP root_dir → `.git`, `.venv`, `venv`,
`pyproject.toml`, `uv.lock`, `package.json`, `go.mod`, `Cargo.toml`, `CMakeLists.txt`,
`Makefile` → текущая директория. Поэтому Explorer не вылезает за рамки проекта,
даже если ты сделал `cd` вверх. Список маркеров — `vim.g.root_spec` в
`lua/config/options.lua`.

Папки свёрнуты: содержимое видно после `l` / `Enter` на папке.

> ⚠️ `Space cn` переименовывает **символ** (переменную/функцию) в коде, а **не файл**.
> Для переименования файла используй `r` в Explorer (`Space E`).

### Панель коммита (`Space eg`) — как в PyCharm

Список файлов, которые изменились по git, поле сообщения коммита снизу и кнопки:

| Клавиши | Действие |
|---------|----------|
| `Tab` | отметить / снять отметку с файла под курсором |
| `Enter` | то же отметка |
| `Ctrl-a` | отметить все файлы (`git add -A`) |
| `Ctrl-c` | **Commit** — коммит того, что отмечено, с текстом из поля |
| `Ctrl-p` | **Push** |
| `Ctrl-r` | откатить файл (discard) |
| `q` | закрыть панель |

Слева в списке видно статус файла: `M` изменён, `A` добавлен, `??` новый. Отмеченные
файлы помечаются, а `Ctrl-c` коммитит только отмеченные — неотмеченные остаются
в рабочей копии. Сделано на snacks-пикере `git_status` в `lua/plugins/ui.lua`.

### Drop через rebase todo (после `Ctrl-d` в `Space gl`)

Откроется todo-список rebase. На строке нужного коммита:
`Ctrl-a` циклит pick → edit → fixup → squash → reword → **drop**.
Выйти и применить: `:wq`. Отменить rebase: `Space gm` (abort).

### Diff / Merge / Rebase — хоткеями (как в PyCharm)

Открой `Space gd` (или Diffview откроется сам при merge/rebase-конфликте).
Слева — твоя версия, справа — новая. Курсор в изменённые строки:

| Клавиши | Действие |
|---------|----------|
| `do` | **взять** изменение из другого окна (diff obtain) |
| `dp` | **отдать** изменение в другое окно (diff put) |
| `]c` / `[c` | след. / пред. изменение (hunk) |
| `s` | stage файла (в панели файлов Diffview) |
| `Space` в панели | toggle stage |
| `q` | закрыть Diffview |

**Merge-конфликты** (3 окна: OURS | THEIRS | результат, курсор внутри конфликта):

| Клавиши | Действие |
|---------|----------|
| `]x` / `[x` | след. / пред. конфликт |
| `Space co` | принять **СВОЁ** (ours) |
| `Space ct` | принять **ЧУЖОЕ** (theirs) |
| `Space cb` | принять BASE |
| `Space ca` | принять **ОБА** (all) |
| `Space cO` | весь файл: СВОЁ |
| `Space cT` | весь файл: ЧУЖОЕ |
| `Space cA` | весь файл: ОБА |
| `dx` | удалить блок конфликта (взять ничего) |

После решения конфликтов: сохрани (`Ctrl-s`), `Space gd` → `s` (stage файлов) → `Space gM` (continue).

## 🔍 Поиск и замена слова в файле

| Клавиши / команда | Действие |
|--------------------|----------|
| `*` | найти следующее вхождение под курсором |
| `#` | найти предыдущее вхождение под курсором |
| `n` / `N` | след. / пред. совпадение (с центрированием) |
| `:s/старое/новое/` | заменить первое вхождение **в текущей строке** |
| `:s/старое/новое/g` | заменить **все** вхождения в текущей строке |
| `:%s/старое/новое/g` | заменить **все** вхождения во **всём файле** |
| `:%s/старое/новое/gc` | заменять с подтверждением (y — да, n — нет, a — все, q — выйти) |

**Заменить только в выделенном блоке:** выдели текст (`V` / `v`), затем `:s/старое/новое/g` — префикс `'<,'>` добавится сам.

**Быстрый способ:** наведи курсор на слово → `*` → набери `:%s//новое/g` (пустой `//` использует последнее искомое слово).

## ⚙️ C / C++ (gcc)

Работает в файлах `c`, `cpp`, `objc`, `objcpp`. Хоткеи в терминале: `Esc Esc` — выйти в Normal.

| Клавиши | Действие |
|---------|----------|
| `Space CR` | ▶ собрать и сразу запустить: `gcc -g -Wall -Wextra main.c -o main && ./main` |
| `Space Cb` | 🔨 только собрать (без запуска) |
| `Space Cd` | 🐛 отладка: `lldb ./main` |
| `Space Cq` | 📋 собрать, ошибки в quickfix |
| `Space Cl` | 🧹 закрыть терминалы сборки/запуска |

Как это работает:
- **Компилятор по типу файла:** `c` → `gcc`, `cpp`/`objc`/`objcpp` → `g++`.
- **Бинарь** собирается рядом с исходником: `main.c` → `main`. Запускается как `./main`.
- Окно терминала **не закрывается само** после завершения программы — вывод остаётся, его можно скроллить. Закрыть — `Space Cl`; повторный `Space CR` пересоздаёт окно с нуля.
- **Сборка всегда с `-g`**, поэтому `lldb` видит имена функций, переменных и номера строк.
- В `lldb`: `b main` — breakpoint, `r` — запустить, `n` / `s` / `c`, `bt` — стек, `q` — выход.
- `Space Cq` кладёт ошибки в quickfix: переход по ним — `:cnext` / `]q`, или `Trouble` (`Space cD`).
- Хоткеи `Space CR`/`Cb` в заголовке (`.h`) не сработают — откройте `.c` / `.cpp`.
- Собирается **один файл**. Для многофайловых проектов нужен `make` / `cmake`.
